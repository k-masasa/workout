### 取得方法

```bash
$ for p in 1 2 3; do
    curl -s "https://api.hevyapp.com/v1/workouts?page=$p&pageSize=10" \
      -H "api-key: $HEVY_API_KEY" > /tmp/hevy_p$p.json
  done
$ jq -s '[.[].workouts[]] | map(...)' /tmp/hevy_p1.json /tmp/hevy_p2.json /tmp/hevy_p3.json
```

- **罠**: Public API の `pageSize` は **上限 10** らしい (pageSize=30 で空レスポンス + curl exit 5)。複数ページ取得が必須。
- workout_count エンドポイント (`/v1/workouts/count`) で全件数 (21) を先に把握してから page 数決定すると確実。

### 整形ルール (今回採用)

- 種目名は短縮 (例: 「シーテッドショルダープレス　（マシン）」 -> 「ショルダープレス」)
- 形式: `種目 重量×top_reps×sets` (sets=1 のときは省略)
- 有酸素は距離 + 時間 (時間が秒入力の場合あり、要素見て判断)
- PR マークは現行 `PR (種目別ベスト)` テーブルと整合する日のみ (追加分は本人手で見直す前提)

### 罠 / 学び

- Hevy の duration_seconds は **入力単位が一貫してない** ことがある (6/11 ウォーキング = `duration_seconds: 30` だが実際は 30 分。本人入力時の単位ミス可能性大)。本ファイル + README の表示は実態に合わせて手で補正済み。
- 種目名に **半角 + 全角の空白混在** (例: `ラットプルダウン　(ケーブル)`) があるので、文字列マッチ前提のスクリプト作る時は normalize 必須。
